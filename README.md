## Before publishing
1. Open `script.js` and replace `YOUR_EMAIL_HERE` with a real, monitored business email address.
2. Review the Privacy, Terms and Cookies pages. They are starter templates, not legal advice. Replace placeholders and make sure they accurately describe your business, services, data handling and third-party tools.
3. Confirm your real pricing and service terms. The pricing page deliberately uses custom quotes because no final prices have been confirmed.
4. Replace sample portfolio concepts with real work only when you have permission to show it. Do not imply sample concepts are completed client projects.
5. Add any final business contact details and check all page links.
6. Test on phone and desktop, then check spelling, form behaviour and accessibility.
7. Use GitHub Pages only for the static site itself. It does not run a backend or provide a database. The contact form currently prepares a `mailto:` email and does not save enquiries to a database. A visitor needs an email app configured for it to work smoothly.

## Deploy to GitHub Pages
1. Create a GitHub repository for the site.
2. Upload all files and the `assets` folder, preserving the folder structure.
3. In repository Settings → Pages, select deployment from the main branch/root (or the equivalent current GitHub Pages option).
4. Once published, test the GitHub Pages URL.
5. After registering your domain, configure the custom domain in GitHub Pages and add the DNS records required by GitHub's current documentation. DNS changes can take time to propagate.
